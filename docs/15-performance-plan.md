# 15. 성능과 메모리 검증 계획

2026-09-23. 요구사항 REQ-007/018/046, TV-012. 아직 실측 결과 없음.

## 1. 비교 원칙

기준은 사용자가 실제 사용하는 VS Code+OMP 터미널 구성이다. VS Code를 12개 열었다고 임의 가정하지 않는다. 같은 Windows 기기에서 같은 프로젝트·확장·OMP/모델·세션 크기·언어 서버·서버 수·빌드 요청을 비교한다.

3개와 12개 메인 작업이 실제 동시에 코드 수정/명령 실행하는 구간을 만든다. 숨긴 작업의 IDE 분석은 유지한다. 하위 에이전트 숫자·깊이·활동도 기록하되 고정 숫자 제한으로 목표를 달성하지 않는다.

## 2. 시험 행렬

| ID | 부하 | 관측 |
| --- | --- | --- |
| PERF-01 | 3개 작업, 안정 대기·편집·전환 | 기본 메모리·CPU·자동완성 지연 |
| PERF-02 | 12개 작업 실제 병렬 실행 | 최대 부하·프로세스 수·프레임 응답 |
| PERF-03 | 하위 생성·완료 반복 | 누수 추세·이력 캐시 증가 |
| PERF-04 | 대화·도구 출력 대량 스트리밍 | UI 정체·stdout 소비·디스크 사용 |
| PERF-05 | 작업 전환 100회, 디버깅 1개 유지 | 서비스 재시작 횟수·문맥 혼입 |
| PERF-06 | 2시간 지속, 완료/정리 반복 | 메모리 회수·잔존 프로세스 |
| PERF-07 | 큰 파일 diff·이력 탐색 | worker 응답·취소·최대 메모리 |

각 구성 최소 3회, 순서는 번갈아 실행한다. 안정화 5분·활동 30분·지속 2시간은 설계 초깃값이다. 초기 인덱싱 비용은 별도 결과로 남긴다. 원격 모델의 응답 변동을 기록하고 앱 처리 시간과 모델 대기 시간을 분리한다.

## 3. 지표와 수집

프로세스 트리 전체의 Private Bytes, Private Working Set, CPU, I/O, PID/시작 식별자, 서버·언어 호스트 개수를 1초 간격으로 기록한다. 공유 메모리 중복 합산을 피한다. 로컬 모델·DB·개발 서버 포함/제외 범위를 명시한다.

타임스탬프는 단조 시계로 동작 지연을 측정한다. 카드 이벤트 수신→화면 반영, 탭 클릭→기존 내용 표시, 자동완성 요청→결과, 중단 요청→실제 정지, 복원→목록 표시를 측정한다.

임시 개발 목표: warm 탭 표시 p95 300ms 이하, 카드 반영 p95 500ms 이하. 이는 사용자 확정 SLA가 아니며 환경 실측 후 조정 가능하다. 조정 이유·전후 값을 기록한다. 서비스를 재시작해서 생기는 지연은 따로 표시한다.

## 4. 결과 형식

각 run은 environment.json, process-samples.csv, interaction-latency.csv, workload.md, result.md를 생성하도록 측정 도구를 구현한다. CSV 필드: runId,configuration,timestamp,pid,startIdentity,role,privateBytes,privateWorkingSet,cpuPercent. 개인정보·토큰은 포함하지 않는다.

비교 결과에 중앙값·피크·p95와 실행별 분산, 앱 외부 프로세스 영향, 실패 횟수, 주의점을 적는다. 감소율은 (기준-후보)/기준×100으로 계산한다. 기준 0 또는 측정 누락은 계산하지 않는다.

## 5. 판정

기능 조건이 먼저 충족되어야 한다. 3개·12개 조건 모두에서 반복 측정의 변화가 잡음 수준을 넘고 메모리 중앙값·피크의 감소가 일관되는지 확인한다. 혼재/미미하면 '보류'다. 숫자 최소 절감률은 아직 사용자 미결정이며 실제 결과가 나오면 수용 판단을 요청한다.

불합격 시 우선 화면 가상화·증분 기록·중복 감시·큰 이력 로딩을 최적화한다. 사용자가 거절한 비선택 분석 종료·실행 슬롯 축소는 자동 채택하지 않는다. 기본 프로그램 완성 여부와 RAM 목표 달성 여부를 별도로 보고한다.

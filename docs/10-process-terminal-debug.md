# 10. 프로세스·터미널·디버깅 명세

2026-09-23 / 설계 기본값. 연결: [상태](05-task-lifecycle.md), [IDE](11-ide-extensions.md), [복구](14-recovery-diagnostics.md).

## 1. 소유 그룹

각 프로세스는 taskId, processId, OS PID, 시작 식별자, 실행 파일, cwd, role, parent, ownerGroup을 가진다. 명령의 비밀 인자는 로그에서 가린다. 역할은 agent, foreground-command, development-server, terminal, debugger다.

앱 소유와 외부 소유를 구별한다. 외부에서 시작된 서버를 포트가 같다는 이유로 종료하지 않는다. Windows는 Job Object 등 소유 프로세스 그룹 기능을 검증해 사용하되 서버·터미널은 에이전트 중단 그룹과 분리한다. 구현 언어·native binding은 TV-008 검증 결과로 고정한다.

## 3. 중단 절차

abort를 보내고 실제 엔진·자손·foreground 종료를 관측한다. 5초 후에도 미완료면 '중단 처리 중'과 남은 실행을 표시한다. 15초를 넘으면 강제 중단 선택지를 제공한다. 강제 중단은 확인된 에이전트 소유 그룹만 대상으로 하며 서버 그룹을 포함하지 않는다.

타임아웃은 UI 완료 판정 기준이 아니다. 작업을 paused로 바꾸는 시점은 정지 확인 후다. 종료 불명은 failed/unknown 진단으로 남긴다. 특정 프로세스 종료 전 PID와 시작 식별자를 다시 대조한다.

## 4. 서버와 포트

포트 기본 풀 3000~9999, 후보 점유 검사 후 lease 생성, 실제 bind 성공 후 bound. 같은 포트라도 host/주소군 차이를 감안한다. OS가 허용한 임시 포트 사용은 해당 서버가 지원할 때만 선택한다. 포트 선점이 생기면 새 lease를 배정하고 에이전트에 변경 정보를 전달한다.

앱은 프레임워크 설정을 임의 정규식으로 수정하지 않는다. 에이전트가 지정 포트로 실행하고 실제 URL·프로세스를 서버 등록 도구로 보고한다. URL은 허용한 http/https와 로컬 host·등록 포트를 대조한다. 외부 브라우저 열기는 서버 준비 상태를 확인한다.

서버 등록이 없는 무기한 셸 명령을 자동으로 서버라고 추정하지 않는다. 장시간 동작의 소유 역할을 명시해야 중단·종료 범위를 보장할 수 있다.

## 5. 터미널

Windows PTY 백엔드는 후보 IDE의 지원 기능을 우선 활용한다. 각 작업에 터미널 1개를 필요할 때 만들고 추가 탭을 허용한다. cwd는 해당 워크트리, 새 논의 화면에는 실행 터미널을 만들지 않는다.

출력은 taskId/processId로 분리하고 화면에는 가상 스크롤을 적용한다. 기본 메모리 스크롤백 10,000줄, 초과분은 회전 로그로 관리한다. 터미널 로그는 대화와 별도다. 탭 닫기와 PTY 종료 버튼을 구분한다.

## 6. 디버깅

선택 워크트리의 launch 설정과 확장 디버거를 사용한다. breakpoints, watch, call stack은 taskId 문맥이다. 작업 전환으로 detach/stop하지 않는다. 다른 작업의 동일 클래스 경로로 소스 매핑하지 않는다.

에이전트가 소스를 수정하면 '실행 코드와 파일이 다를 수 있음'을 표시한다. 자동 재시작하지 않고 Restart 액션으로 재시작한다. debugger 역할 종료 시 디버깅 대상 프로세스까지 종료할지는 해당 launch/attach 의미를 따른다. attach한 외부 서버는 앱 소유로 전환하지 않는다.

## 7. 검증

TV-008/013에 더해 자손 2단계, PID 재사용, PTY 닫기, 서버 충돌, attach 디버깅, 앱 종료 중 엔진 멈춤을 확인한다. 프로세스 개수 고정으로 메모리 요구를 달성했다고 처리하지 않는다.

# 16. 수용 시나리오와 검증 명세

2026-09-23. 테스트 코드가 이미 있다는 뜻이 아니라 구현 완료를 판정할 실행 계약이다. [요구사항](03-requirements-traceability.md), [상황별 시나리오](04a-interaction-scenarios.md), [기술 검증](01-technical-validation.md).

## 1. 검증 계층

순수 상태·대기열·정책은 단위 검증, 실제 Git/SQLite/PTY는 통합 검증, OMP/IDE/Windows 화면은 실제 연동 검증으로 수행한다. 모의 엔진 성공은 실제 OMP 성공을 대체하지 않는다. 플랫폼 기능은 Windows 증거가 필요하다.

사용자가 에이전트 작업마다 테스트를 강제하지 않기로 한 결정은 본 제품 자체의 데이터 유실·잘못된 중단·중복 반영 검증을 면제하지 않는다. 변경 영향과 관련 없는 전부 재시험은 요구하지 않는다.

## 3. 장애 주입

- DB commit 전/후 프로세스 종료: operation과 이벤트 일관성.
- 프레임 조각 누락·응답 역순·large frame: 프로토콜 오류 격리.
- Git 준비 각 단계 실패: 원본 보존·소유 자원만 정리.
- 대상 dirty worktree·PID 재사용·포트 선점: 잘못된 덮어쓰기/종료 방지.
- 저장 매체 가득 참·권한 거절: 편집 버퍼 보존과 실행 차단.
- 승인 후 파일/정책/HEAD 변경: E_APPROVAL_STALE.
- import 복사 중 원본 변경: 새 프리뷰 요구.
- 탭 닫기 중 draft 영속화 실패: 닫기 중단·복구 제공.

## 4. 증거와 완료 기준

결과 파일 필수: AT ID, 빌드 커밋, 환경·버전, 사전 조건, 실제 단계, 기대/실제, 상태 PASS/FAIL/BLOCKED, 로그·스크린샷 링크. 통과한 척하지 않도록 NOT_RUN도 허용한다. UI 검증은 원래 요청·현재 행동·오른쪽 세션·왼쪽 트리·탭 동작을 캡처한다.

중대한 데이터 유실, 잘못된 작업 코드 수정, 중복 외부 반영, 중단 대상 오인, 정렬용 빈 행 생성은 출시 차단이다. TV-012 보류면 메모리 목표 달성을 주장하는 릴리스는 금지한다. 나머지 미완료 기능은 범위를 명시한 개발용 프리뷰로만 제공한다.

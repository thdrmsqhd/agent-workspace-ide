# 04a. 상황·버튼·액션별 시나리오 정의서

2026-09-23 / 구현 기준. [화면](04-screen-specification.md), [API](07-api-events.md), [상태](05-task-lifecycle.md).

## 1. 공통 계약

아래 각 SCN의 버튼·단축키·자동 사건은 같은 행동 계약을 공유한다. 행의 순서는 사전 조건 → 사용자/시스템 동작 → 즉시 화면 반응/내부 처리 → 성공 결과 → 실패·보존 규칙이다. 각 SCN은 동일 번호 ACT를 가지므로 예를 들어 SCN-004의 조작 ID는 ACT-004다.

일반 성공: 서버 수락 이전에는 성공으로 표시하지 않음. 변경 작업 중 해당 버튼은 중복 요청을 방지하되 다른 작업의 UI는 사용 가능. 엔진 작업의 수락과 최종 종료는 별도 표시한다.

일반 실패: 오류 code와 다음 조작을 표시하고 초안·미저장 버퍼·원래 요청·기존 파일을 보존한다. 자동 rollback을 제공하는 척하지 않는다. 이전에 완료한 외부 부작용이 있으면 정확히 표시한다. 재시도는 14의 규칙을 따른다.

읽기/화면 이동은 중복 실행해도 같은 결과. 변경 명령은 requestId로 중복 방지. Esc는 현재 문맥에서만 처리한다. 삭제·파일 버리기·강제 종료 등 데이터에 영향을 주는 동작은 이 표에서 정한 대상을 확인한다.

## 3. 동시 조작 우선순위

1. 탭 전환/닫기는 작업 상태를 변경하지 않는다.
2. Esc는 아직 인계되지 않은 큐 소비보다 우선한다. 이미 인계 중이면 수락 여부를 확인하고 중단한다.
3. queued 편집/삭제와 인계는 같은 revision 조건으로 경쟁하며 하나만 성공한다.
4. 빠른 답변과 작업 대화 답변은 같은 inputId를 잠근다. 한 번 확정 후 나머지는 만료 응답이다.
5. 승인 후 코드·대상 HEAD·정책이 변하면 기존 승인이 더 이상 유효하지 않다.
6. 작업 영구 삭제와 재개는 같은 task revision을 확인하며 실행 중인 작업을 삭제하지 않는다.
7. 앱 종료 시작 후 신규 실행 요청은 거절하고 초안 저장만 허용한다.

## 4. 구체적 예외 흐름

### SCN-012-E1 — 탭 닫기 중 저장 실패

A 탭의 입력/dirty 버퍼를 보존하려다 디스크 부족 → 탭 유지 → '화면을 닫기 전에 편집 내용을 저장할 수 없습니다' → 재시도/다른 위치 저장. 사용자가 데이터 손실을 명시적으로 감수하지 않는 한 조용히 닫지 않는다. 엔진은 별도 작업 중단 정책이 발생하지 않았다면 계속 실행한다.

### SCN-020-E1 — 대기 지시 편집과 실행 시작 경합

사용자가 M2를 수정하는 동안 백엔드가 dispatching 선점 → revision 불일치 → 편집본을 초안으로 남기고 '이미 전달 중입니다. 추가 지시로 보낼 수 있습니다' 표시. 전달한 M2 원문을 이력에서 바꾸지 않는다.

### SCN-029-E1 — 중단 확인 지연

abort 수락 후 자손 실행 지속 → stopping 유지 → 5초 후 남은 실행 목록 → 15초 후 강제 중단 선택. 타임아웃만으로 paused 표시하지 않는다. 개발 서버는 강제 중단 그룹에서 제외한다.

### SCN-051-E1 — 승인 직후 대상 변경

승인 payload의 expectedTargetHead와 현재 HEAD 불일치 → 반영 안 함 → 새 반영 diff 생성 → 승인 재요청. 수동 승인 상태를 자동 승인으로 바꾸지 않는다.

### SCN-054-E1 — push 응답 유실

로컬 병합 완료, push 응답 전 연결 종료 → 로컬 성공은 유지, 원격 unknown → 원격 ref 조회. 이미 반영됐으면 다음 단계, 미반영이 확정되면 재시도, 확인 불가면 대기. 동일 커밋을 다시 만들지 않는다.

### SCN-061-E1 — 종료 도중 기록 실패

종료 요청 후 state flush 실패 → 창을 유지하고 저장 실패 표시. 실행 중단이 이미 완료됐다면 그 사실은 유지한다. 사용자가 재시도해도 이미 종료된 프로세스를 다시 실행하지 않는다.

## 5. 추가 UI를 만들 때

새 버튼·단축키·메뉴·드래그를 추가하면 ACT/SCN과 CMD 또는 UI-only 여부를 반드시 연결한다. 같은 기능의 단축키는 기존 SCN을 재사용한다. 이 표에 없는 계정 관리·팀 협업·과금 화면은 임의로 추가하지 않는다.

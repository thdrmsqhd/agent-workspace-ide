# 09. Git·워크트리·반영 명세

2026-09-23. 연결: [정책](13-workflow-permissions.md), [상태](05-task-lifecycle.md), [복구](14-recovery-diagnostics.md).

## 1. 등록과 기준

repo_key는 Git 공통 디렉터리의 실제 경로에서 계산한다. 같은 저장소를 다른 worktree 경로로 등록해도 동일 반영 잠금을 사용한다. 기본 대상 브랜치는 remote HEAD가 가리키는 로컬 추적 브랜치, 없으면 현재 로컬 브랜치다. 둘 다 불명확하면 작업 시작 전에 선택하도록 한다.

명령은 git 실행 파일과 인자 배열로 호출하며 '--' 구분, 허용된 cwd, 정규화된 경로를 사용한다. 브랜치명은 Git 검증을 통과해야 한다. 네트워크 fetch는 명시한 워크플로우 또는 사용자 요청 시 수행하고 자동으로 대상 HEAD가 바뀐 사실을 숨기지 않는다.

## 2. 작업 생성

브랜치명 설계값: awi/task/{taskId}. 기존 브랜치와 충돌하면 다른 작업 자원을 재사용하지 않는다.

단계: 요청 저널 → 기준 커밋·대상 ref 고정 → git worktree add -b → 디렉터리 확인 → task 연결 → 엔진 초기화 → 실행 가능. 중간 실패는 저널의 소유 증거가 있는 자원만 정리한다. 워크트리 파일 수정이 이미 있으면 삭제하지 않고 복구 안내한다.

비Git 폴더는 읽기·논의 가능, 실행 전 Git 저장소 준비가 필요하다. 사용자 모르게 git init·기존 파일 커밋을 수행하지 않는다.

## 3. 가져오기

프리뷰에는 base/head, 파일별 changeKind, 원본 해시, 크기, 선택 여부를 담는다. 초기 전체 선택은 Git 변경 목록에 한정한다. ignored 파일은 별도 명시적 선택, .git 내부는 복사 금지다.

스테이징/미스테이징을 모두 확인하되 새 워크트리에는 최종 작업 파일 내용을 재현한다. 원래 staging 분류까지 보존하는 기능은 첫 버전 범위가 아니다. rename은 이전/새 경로를 한 선택 단위로 취급한다. 바이너리는 원시 바이트로 복사한다.

복사 전후 원본 해시/HEAD가 변하면 프리뷰 만료. symlink·junction은 경계를 벗어나 따라가지 않으며 지원하지 않는 유형은 실행 전에 목록으로 거절한다. 적용 뒤 선택 파일 해시와 삭제 상태를 비교하고 세션을 새 경로로 준비한다.

## 4. 변경 검토

작업 최초 baseCommit과 현재 디스크를 비교하는 작업 diff가 기본이다. 반영 직전에는 최신 targetHead와 통합 결과의 diff를 별도로 표시한다. 이름을 각각 '작업 변경'과 '반영 변경'으로 표시하여 기준을 혼동하지 않는다.

검토 snapshot에는 기준 커밋·작업 head·미커밋 파일 manifest·내용 해시를 넣는다. 승인은 snapshotId+targetHead+policyHash에 묶인다. 그 뒤 파일·HEAD·정책이 변하면 승인 무효다.

## 5. 반영 알고리즘

같은 repo_key에서 하나씩 실행한다. target branch가 사용자의 원본 작업 폴더에 checkout되어 있을 수 있으므로 직접 reset/checkout하지 않는다.

1. 실행·자손 도구가 정리됐는지 확인하고 작업 쓰기 임대 차단. 미저장 버퍼가 있으면 해결 대기.
2. 워크플로우가 요구하는 검증·커밋을 수행하고 결과를 기록.
3. repo 잠금 확보, targetHead 재조회, stale 승인 재평가.
4. 전용 임시 통합 브랜치와 워크트리에서 병합 결과 후보 생성. 충돌은 여기 보존.
5. 대상이 어떤 워크트리에도 checkout되지 않았으면 expected old SHA 조건부 ref 갱신.
6. 대상이 checkout된 워크트리가 있으면 해당 디렉터리가 깨끗하고 변경 주체가 없는지 확인 후 Git 정상 fast-forward 절차로 후보 커밋 반영. 수정/미저장/실행 중 대상이면 대기. 강제 덮어쓰기 금지.
7. 성공 SHA 기록 후 필요 시 push·PR. 로컬 병합과 원격 단계는 별도 성공 상태.

외부 편집자와 앱이 공유하는 Git 잠금이 없으므로 외부 파일 변경을 완전히 원자적으로 막는다고 주장하지 않는다. 직전/직후 상태 검증과 Git 오류로 실패를 감지한다. 불확실 시 자동 진행을 중단한다.

## 6. 충돌·재시도·PR

충돌 워크트리에서 해결하고 conflict.continue로 unresolved index가 없는지 검사한다. 대상 HEAD가 이동했으면 최신 대상 기준으로 다시 통합한다. 충돌 작업이 repo 잠금을 영구 점유하지 않게 저널 상태 저장 후 반환한다.

push 응답을 잃으면 원격 ref 조회로 확인한다. PR 응답을 잃으면 작업 메타데이터·head/base로 기존 PR을 조회한다. 같은 작업에 PR을 중복 생성하지 않는다. 지침이 PR-only면 로컬 대상 병합을 선행하지 않는다.

병합 방식(merge/squash/PR-only)은 워크플로우 우선, 명시 없을 때 앱 기본은 로컬 merge 후보를 제안하고 수동 승인받는다. force push는 기본 금지이며 별도 명시적 사용자 지시 없이는 실행하지 않는다.

## 7. 정리

정리 조건: 병합됨, 미반영 파일 0, dirty buffer 0, 소유 실행 프로세스 0, 디버거 0, 다른 작업 참조 0, 이력 스냅샷 보존 완료. git worktree remove를 정상 호출하고 실패 시 보존한다. force나 임의 디렉터리 재귀 삭제로 성공을 꾸미지 않는다.

워크트리를 없애도 앱 검토 snapshot은 유지한다. 브랜치 삭제는 병합 관계가 확인된 앱 소유 브랜치에 한정한다. 원본 프로젝트와 원래 세션은 삭제하지 않는다.

공식 Git 동작 참고: https://git-scm.com/docs/git-worktree . 실행 검증: TV-007/009.

## 8. 구현 상태

`packages/worktrees`는 Git 공통 디렉터리 키, 기준 커밋·앱 소유 브랜치·워크트리, 준비 저널을 만들고 재사용을 거절한다. `packages/worktrees/import`는 staged/unstaged/미추적/삭제/rename 변경을 원본 해시로 프리뷰하고 새 워크트리에 선택 적용한다. ignored 파일·symlink는 기본 가져오기 대상이 아니며 원본 폴더를 수정하지 않는다. 적용 도중 오류가 나면 대상의 부분 결과를 진단 대상으로 보존한다. OMP 대화 문맥 이전, 다중 단계 보상, 병합·push·PR·정리는 아직 구현하지 않았다.

## 문서의 역할과 현재 상태

이 문서는 검증을 수행할 에이전트에게 입력 조건·수행 순서·통과 기준·실패 시 조치를 제공한다. TV-003/004/006은 2026-09-23에 실제 엔진(Windows, OMP 18.2.5)으로 실행했고 결과는 [TV-003](evidence/TV-003/README.md)·[TV-004](evidence/TV-004/README.md)·[TV-006](evidence/TV-006/README.md)에 있다. 나머지 검증과 IDE 호스트 검증(TV-001/002)은 미실행이다.

문서 확인과 실행 검증을 구별한다. 상태는 미실행 → 실행 중 → 통과/실패/환경 차단으로 기록한다. 문서에서 명령을 발견한 것만으로 통과 처리하지 않는다. 실행 환경이 없으면 환경 차단으로 남기고 모의 구현 결과를 실제 엔진의 통과 근거로 사용하지 않는다.

## 1. 공개 자료에서 확인한 사실

| 근거 | 확인 내용 | 여전히 확인할 사항 |
| --- | --- | --- |
| S1 OMP RPC | stdio RPC, prompt·steer·follow_up·abort, 상태 조회, 세션 전환, 하위 에이전트 구독/조회가 문서화됨 | 선택 버전에서 동작, 모든 자손 중단, 기존 작업 경로 이동 |

## 2. 검증 환경과 공통 산출물

실행 담당은 Windows 로컬 개발 환경을 사용한다. OS 빌드, CPU/RAM, Git·OMP·IDE·Node/Bun·JDK·Python·확장의 정확한 버전과 배포 출처를 기록한다. 여기서는 미검증 버전 번호를 임의로 고정하지 않는다. 최초 재현 가능한 조합을 만든 후 lockfile과 실행 바이너리 해시를 보존한다.

공통 시험 자료:

- Java 프로젝트: 클래스 두 개, 교차 파일 호출, 중단점, 지역 변수, 이름 변경 대상.
- Python 프로젝트: 모듈 두 개, 타입이 있는 함수, 교차 모듈 자동완성·선언 이동.
- Git 프로젝트: 초기 커밋, 텍스트·바이너리 파일, 이름 변경·삭제·미추적 파일, 공백/한글 경로.
- 독립 개발 서버와 짧은 빌드 명령, 중단 가능한 장시간 명령, 자식 프로세스를 만드는 명령.
- 실제 엔진 검증에서는 시험용 저장소·인증을 사용한다. 모델 응답 차이를 제어할 수 있도록 요청·도구 호출·실행 시간을 기록한다.

각 검증의 결과는 향후 docs/evidence/TV-번호/에 기록한다. 필수 항목: 실행일, 정확한 버전, 사전 조건, 실행 명령, 기대/실제 결과, 로그·스크린샷 경로, 통과 여부, 잔여 제한, 연결 요구사항·ADR. 비밀값은 기록하지 않는다. 실패를 요구사항 삭제로 해결하지 않는다.

## 4. 실행 순서와 차단 범위

1. TV-001/002와 TV-003을 먼저 수행한다. 전자는 IDE 기반, 후자는 OMP 연결의 기본 가능성을 판단한다.
2. TV-004/005/006으로 대화·하위 작업·실행 권한을 검증한다.
3. TV-007~011/013/014를 검증한다. Git·저장·프로세스의 단위 개발은 IDE 채택과 독립적으로 진행할 수 있다.
4. TV-012의 소규모 예비 측정은 TV-001~003 직후 시작하고, 최종 3개·12개 시험은 실제 통합 후 수행한다. 성능 문제를 배포 직전에 처음 발견하지 않는다.

하나가 차단되어도 무관한 도메인 모델·대기열·정적 화면 구현은 계속할 수 있다. 단, 모의 어댑터만 연결된 화면을 실제 실행 기능의 완료로 보고하지 않는다.

## 5. 메모리 판정 프로토콜

현재 구성은 사용자가 실제로 쓰는 VS Code·OMP 터미널 수로 기록한다. 동일 PC에서 같은 프로젝트·확장·세션 크기·서버 수·작업 요청을 사용한다. 3개와 12개를 각각 최소 3회 측정한다. 실행 순서를 번갈아 바꾸고 초기 인덱싱과 안정 상태를 분리한다.

설계용 기본 측정 창: 준비 완료 후 5분 안정화, 30분 활동 측정, 별도 2시간 지속 시험. 이는 사용자 확정 수치가 아니라 재현 가능한 시험을 위한 초깃값이다. 실제 업무 세션 길이에 맞춰 확대할 수 있다.

전용 메모리(Private Bytes), 실제 상주 메모리(Private Working Set), 피크, CPU, 전환 응답을 기록한다. 모델 서버가 로컬이면 포함하고 원격이면 별도 표기한다. 합계에서 제외한 프로세스와 사유도 남긴다.

판정: 기능 조건을 모두 충족하고, 반복 시험에서 중앙값·피크 감소가 측정 변동을 넘어 일관되게 나타나야 한다. 절감률은 숫자로 보고한다. 결과가 혼재하거나 감소가 미미하면 '판정 보류'다. 사용자가 요구한 '확실히 적게'의 최소 퍼센트는 아직 정해지지 않았으므로 임의로 10%·20%를 합격 기준으로 만들지 않는다. 실측 결과를 받은 뒤 최종 수용 여부를 결정한다.

## 8. 실행한 검증과 결과

2026-09-23 Windows 11에서 로컬 설치 엔진(OMP 18.2.5)으로 세 건을 실행했다. 재현 명령은 저장소의 `npm run verify:omp:tv003`·`tv004`·`tv006`이고, 결과 요약과 원시 프레임 로그는 각 검증의 증거 폴더에 있다.

| 검증 | 판정 | 핵심 결과 |
| --- | --- | --- |
| RPC 연결·프레임(TV-003) | 통과 | 1MiB 프레임 한도, v2 청크 재조립 일치, id 결합, 실패 응답에 id 없음, 수락과 완료 분리 |
| 하위 트리·중단(TV-004) | 실패 | 트리·구독·페이징은 동작, `abort` 후 20초간 자손 셸이 계속 실행됨 |
| 읽기 전용 논의(TV-006) | 통과 | 승인 정책 거부와 MCP 설정 차단을 함께 적용해야 논의 모드가 닫힘 |

TV-004 실패로 자손이 있는 작업의 중단은 출시 차단 항목으로 남긴다. 임시 작업대만 사용했고 사용자 프로젝트·세션·전역 설정은 변경하지 않았다.

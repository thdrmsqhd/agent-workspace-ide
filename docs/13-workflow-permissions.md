# 13. 워크플로우와 실행 권한 명세

2026-09-23. 관련 REQ-004, REQ-031, REQ-032. [OMP](08-omp-adapter.md), [Git](09-git-worktrees.md).

## 1. 정책 계층

앱은 사용자 명시 지시, 작업 모드, 프로젝트 지침, 엔진 기본 설정을 함께 적용한다. 제품 불변조건(논의 중 쓰기 금지, 작업 격리, 중복 부작용 금지)은 지침 텍스트로 해제하지 않는다.

구체적인 사용자 작업 지시가 프로젝트 일반 지침보다 우선한다. 프로젝트 내 지침 범위는 해당 엔진의 공식 해석을 따르고 앱이 별도 추측 규칙으로 바꾸지 않는다. 충돌하거나 외부 변경 범위가 불명확하면 해당 행위만 질문한다.

워크플로우는 프로젝트가 이미 사용하는 지침을 읽는다. 새로운 필수 DSL·설정 파일을 요구하지 않는다. 단 실행 전에 에이전트가 구조화한 정책 요약을 앱에 제출하고 사용자가 볼 수 있게 한다.

## 2. 정책 스냅샷

PolicySnapshot={mode,sourceFiles:[path,hash],userInstructionIds,allowedActions,requiredChecks,integrationStrategy,targetBranch,remote?,reviewRequired,hash,createdAt}.

allowedActions는 edit,runLocal,merge,push,createPR로 구분한다. 지침이 구체적인 테스트를 요구하면 requiredChecks에 명령·성공 기준을 포함한다. 지침 없음이면 edit/runLocal은 실행 모드 정책에 따르고 merge/push/createPR은 확인 필요로 둔다.

정책이 바뀌면 기존 승인은 무효. 파일 내용이 모델이 판단한 요약과 불일치하면 읽은 출처와 해석을 사용자가 확인할 수 있어야 한다.

## 3. 모드별 표

| 행위 | 논의 | 수동 승인 작업 | 자동 반영 작업 |
| --- | --- | --- | --- |
| 프로젝트 읽기·검색 | 허용 | 허용 | 허용 |
| 코드 쓰기·로컬 명령 | 금지 | 엔진 설정·작업 지시 범위 | 동일 |
| 테스트 | 실행 금지 | 워크플로우에 따름 | 워크플로우에 따름 |
| 병합·push·PR | 금지 | 최신 snapshot 승인 후 | 지침이 명시적으로 허용한 행위만 |
| 지침 없는 외부 반영 | 금지 | 확인 | 확인 |
| 다른 작업 디렉터리 쓰기 | 금지 | 금지 | 금지 |

반영 승인은 해당 snapshot·대상·행위 범위만 허용한다. '승인 후 반영'이 계정 전체의 영구 권한을 뜻하지 않는다. PR-only, 로컬 병합, push까지 등 실제 반영 동작을 버튼 옆에 표시한다.

## 4. 강제 적용 경계

논의 제한은 도구 목록·실행 호스트에서 적용한다. MCP의 읽기/쓰기 특성이 불명확하면 논의 단계에서 허용하지 않는다. 모델이 셸로 우회할 수 있으면 읽기 전용 검증 실패다.

Git 반영은 Worktree Service와 Integration Coordinator를 경유한다. 에이전트의 임의 셸이 원본 대상·원격을 변경하지 못하도록 엔진 도구 훅/호스트 도구로 정책을 검사한다. 단순 명령 문자열 차단 목록만으로 보호가 완성됐다고 보지 않는다. 선택 OMP 버전에서 경계 적용이 불가능하면 해당 흐름은 출시 차단이며 UI 확인창으로 대체하지 않는다.

이 정책은 신뢰하지 않는 코드를 OS 수준 격리하는 보안 샌드박스가 아니다. 일반 개발 환경 권한 아래 동작한다는 한계를 문서화한다.

## 5. 질문·오류·완료

질문은 input_requests로 기록하고 해당 작업만 대기한다. 복잡한 질문도 빠른 답변 대신 작업 열기로 이동 가능하다. 응답 timeout은 자동 승인으로 해석하지 않는다.

필수 검증 실패 시 에이전트가 수정·재시도한다. 확인하지 않은 항목은 미실행, 실패한 항목은 실패로 표시한다. requiredChecks가 없으면 테스트를 했다고 주장하지 않는다.

사용자가 테스트 불필요를 선택한 것은 제품 자체의 데이터 보존·격리 검증을 생략하라는 뜻이 아니다. 제품 개발 수용 검증은 16번 문서에 따른다.

# 04. 화면·상호작용 명세

상태: 구현 기준 v0.2 / 2026-09-23. 연결: [시나리오](04a-interaction-scenarios.md), [상태](05-task-lifecycle.md), [요구사항](03-requirements-traceability.md).

## 1. 확정 배치와 적용 우선순위

사용자가 이미지로 동의한 배치와 이후 탭 결정을 반영한다. 이미지는 참고이며 생성 이미지 속 예시 코드·날짜·자동 테스트 문구는 요구사항이 아니다.

| 영역 | 내용 | 기본 폭·동작 |
| --- | --- | --- |
| 상단 고정 | 새 작업 대상 프로젝트, 요청 입력, 첨부, 전송 | 창 전체 폭. 어느 탭에서도 새 논의 시작 |
| 왼쪽 | 활성 작업의 파일 탐색기 | 기본 240px, 180~420px 조절·접기 |
| 가운데 | 고정 전체 현황 탭 + 작업별 탭 | 나머지 폭. 활성 작업의 대화·편집·터미널 |
| 오른쪽 | 프로젝트 목록과 프로젝트별 에이전트 세션 트리 | 기본 300px, 240~480px 조절·접기 |
| 상태 영역 | 저장 실패·연결 상태·백그라운드 알림 | 에러가 있을 때 표시. 카드 이동 없음 |

폭은 설계 기본값이며 설정으로 보존한다. 창 최소 권장 1100×720, 작은 폭에서는 왼쪽을 우선 접고 중앙에 가로 스크롤을 만들지 않는다. 오른쪽을 자동으로 중앙에 옮기지 않는다. DPI 100/150/200% 확인.

## 3. 탭과 문맥

전체 현황 탭은 항상 존재하고 닫을 수 없다. 같은 taskId의 탭은 하나만 만든다. 파일 편집 탭은 작업 탭 내부의 하위 탭이며 서로 다른 워크트리의 같은 파일명을 혼합하지 않는다.

작업 탭 닫기는 ViewState만 바꾼다. 엔진·서버·디버거는 중단하지 않는다. 작성 중 입력과 미저장 코드 버퍼를 보존하고 오른쪽 세션에 점 배지를 표시한다. 마지막 작업 탭을 닫으면 전체 현황을 활성화한다. 다시 열면 대화 스크롤·입력·커서·패널 상태를 복원한다.

전체 현황에서는 왼쪽 파일 트리를 기본 접는다. 사용자가 펼치면 마지막 작업명을 명확히 표시하고 그 파일을 보여준다. 선택 이력이 없으면 '파일을 볼 작업을 선택하세요'를 표시한다. 전체 현황 진입 때문에 실행 문맥을 바꾸지 않는다.

상단 프로젝트 선택은 새 논의의 대상만 바꾼다. 기존 활성 작업의 프로젝트는 바뀌지 않는다. 오른쪽 프로젝트 제목 클릭은 목록 접기/펼치기, 작업 클릭은 해당 탭 열기다.

## 4. 카드·트리

첫 버전 카드는 프로젝트별 한 열 배치다. 순서는 생성 순(새 항목은 아래)에 고정하며 응답 필요·진행 이벤트 때문에 재정렬하지 않는다. 프로젝트 순서는 등록 순이다. 완료·취소 그룹은 기본 접고 클릭해서 펼친다.

카드: 원래 요청 두 줄과 '더 보기', 상태, 현재 행동/파일명, 최근 활동, 변경 파일 수, 최근 추가 지시, 하위 에이전트 수. 긴 원문은 선택·복사 가능. 응답 필요는 색상+문자+아이콘으로 표시한다.

하위 트리는 기본 접힘. 펼쳐도 직접 지시 입력창은 만들지 않는다. 자식 선택은 읽기 전용 상세를 같은 메인 작업 안에서 표시하며 지시 대상은 항상 메인이다. 엔진 미확인 행동은 '상태 확인 중', 완료율은 근거 없이 생성하지 않는다.

## 5. 중앙 패널

대화가 기본 중심이다. 파일을 열면 대화 옆에 코드 패널, 터미널 열기는 중앙 하단 패널을 사용한다. 패널 분할선 조절과 '확대/복원'을 제공한다. 확대는 다른 패널의 실행을 멈추지 않는다.

준비 중 작업은 파일 읽기 탐색은 가능하지만 실행 버튼과 쓰기 도구는 제한한다. 시작 설정에는 기준 브랜치, 모델, 실행 모드, 적용 범위를 표시한다. 시작 클릭으로 바로 준비 처리하고 불필요한 추가 확인은 띄우지 않는다.

## 6. 입력·키보드

| 조작 | 처리 |
| --- | --- |
| Enter | 해당 입력창 전송. 한국어 IME 조합 중에는 전송하지 않음 |
| Shift+Enter | 줄바꿈 |
| Ctrl+Enter | 동일한 전송 동작 |
| Ctrl+S | 활성 파일 저장, 대화 입력은 전송하지 않음 |
| Esc | 팝업 닫기 우선. 작업 대화 문맥에서는 선택 작업 중단 |
| 터미널 안 Esc | 터미널 입력으로 전달. 작업 중단 버튼은 별도 |
| 코드 선택 후 컨텍스트 메뉴 | '이 코드로 질문' → 해당 작업 대화 초안 첨부 |
| 탭 X | 탭 닫기. 실행 중단과 분리 |

빈 입력+첨부 없음은 전송 비활성. 첨부만 있는 전송은 허용하며 요청이 없음을 에이전트가 알 수 있도록 전달한다. 즉시/대기 선택은 작업별 보존, 최초 즉시. 전달 중에는 같은 초안을 중복 전송하지 않는다. 새 초안 입력은 가능하다.

## 7. 빈 화면·오류·접근성

프로젝트 없음: 등록 버튼과 간단한 설명. 작업 없음: 상단 요청 안내. 필터 결과 없음: 필터 해제. 데이터 로딩은 골격 화면, 연결 오류는 재시도 가능한 배너로 구별한다.

버튼 비활성은 이유를 툴팁·접근성 이름으로 제공한다. 모든 아이콘 버튼에 이름을 부여하고 키보드로 접근 가능하게 한다. 알림은 초점을 빼앗지 않는다. 코드·요청 전문은 스크린리더에서 잘리지 않는다.

## 8. 조작의 권위 문서

상황/버튼/액션별 동작은 [04a](04a-interaction-scenarios.md)가 정의한다. 화면은 CMD 계약을 호출하고 성공 이벤트에 따라 상태를 표시한다. 화면 자체가 Git·프로세스를 직접 실행하지 않는다. 출시 기능 목록은 REQ-001~050이며 패널 폭 등 설계값은 요구사항 축소 없이 조정 가능하다.

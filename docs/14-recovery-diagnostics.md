# 14. 오류·복구·진단 명세

## 2. 재시도 규칙

앱 연결 재시도 초깃값은 1초, 2초, 4초, 8초, 15초 간격 총 5회다. 지터 ±20%를 적용한다. 상태 조회 등 읽기만 자동 반복하며 부작용 명령은 같은 규칙으로 반복하지 않는다. 사용자 수동 재시도는 새 operation을 만들되 이전 저널을 참조한다.

프로토콜 깨짐은 통신 재접속만으로 정상으로 간주하지 않는다. 파서 오류·버전 불일치 진단을 먼저 노출한다. 재연결 중 추가 입력은 초안으로 보존하고 수락 완료로 표시하지 않는다.

## 3. 앱 시작 복구 순서

DB 무결성·스키마 → 미완료 operation → 실제 워크트리·Git 상태 → 프로세스 PID/시작 식별 → 기록 snapshot → 화면 복원. 도구 명령은 재생하지 않는다.

실행 중이던 작업은 paused. discussion·completed·cancelled는 유지한다. integration이 merging/pushing/pr_pending이었다면 결과 조회 완료까지 unknown으로 표시한다. 이전 UI 탭은 복원 가능하나 활성 탭은 전체 현황이다.

## 4. 불확실 부작용

커밋: 작업 tree·HEAD와 저널을 대조한다. merge: 후보 SHA와 target ancestry 확인. push: remote ref 확인. PR: head/base 및 작업 연결 메타데이터 조회. 프로젝트 임의 빌드/마이그레이션 등 의미를 자동 판단할 수 없는 명령은 재실행하지 않고 사용자에게 실제 명령·알려진 결과를 보여준다.

'정확히 한 번 실행'을 네트워크 단절 상황까지 보장한다고 표현하지 않는다. 보장하는 것은 확인되지 않은 부작용을 무조건 재시도하지 않는 것이다.

## 5. 진단 화면

사용자용: 영향 작업, 발생 시각, 간단한 원인, 보존된 내용, 가능한 다음 조작. 개발자용 펼침: errorCode, requestId, operationId, engineVersion, exitCode, 단계, 로그 위치.

로그에 프로젝트 코드·대화·키를 기본 수집하지 않는다. 진단 내보내기는 포함 파일 목록을 보여주고 사용자 동작으로 실행한다. 외부 전송은 자동 수행하지 않는다.

## 6. 종료 실패

정상 종료는 dirty 버퍼와 초안을 먼저 보존한다. 실패하면 종료를 멈추고 별도 저장·재시도를 제공한다. 실행 정리가 지연되면 남은 프로세스와 강제 종료 범위를 표시한다. 강제 종료를 누르면 소유 그룹만 정리하고 복구 표시를 남긴다.

자동 워크트리 정리·파일 GC 실패는 작업 결과 실패와 분리해 '정리 보류'로 표시한다. 완료된 기능 결과를 덮어쓰지 않는다.
